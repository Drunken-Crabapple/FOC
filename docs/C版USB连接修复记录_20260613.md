# C 版 USB 连接修复记录

日期：2026-06-13

## 对照基线

- 原始 C 版：`D:\Desktop\原始C版\FOC-user-c-foc-rebuild-20260613`
- 当前验证版：`D:\Desktop\QDrive_FOC_Rebuild`
- 上传仓库工作区：`D:\Desktop\FOC_github_upload`

原始 C 版的问题是设备可以枚举为 USB 串口，但上位机无法正常连接或打开串口。当前验证版已实机验证可以连接、执行 shell 命令，并能进行电流、速度、低速、角度、步进角度等基本控制测试。

## 关键修复

1. 启动地址修正

   `STM32G431XX_FLASH.ld` 中 `FLASH ORIGIN` 从 `0x08004000` 改为 `0x08000000`。原始 C 版按偏移地址链接，更像有 bootloader 的布局；实际直接烧录运行时，向量表和中断入口不匹配，是不能稳定连接 USB 的关键原因。

2. 向量表重定位修正

   `Core/Src/system_stm32g4xx.c` 关闭 `USER_VECT_TAB_ADDRESS`，并将有效向量表偏移改为 `0x00000000`，与直接从 Flash 起始地址启动一致。

3. USB 时钟校准

   `Core/Src/main.c` 增加 `USB_CRS_Config()`，使用 USB SOF 同步 HSI48，提升 USB 时钟稳定性。

4. USB 初始化位置整理

   `Core/Src/app_freertos.c` 删除 DebugTask 中的 `MX_USB_Device_Init()`，USB 初始化保留在 Shell 启动流程中，避免重复或时序混乱。

5. Shell/CDC 输出初始化

   `Applications/Shell/StartShell.c` 增加 `RetargetInit()`，确保 shell 的 CDC 收发缓冲在使用前完成初始化。

6. CDC 发送缓冲

   新增 `BSP/retarget/cdc_tx_buffer.c` 和 `BSP/retarget/cdc_tx_buffer.h`，`BSP/retarget/retarget.c` 从直接调用 `CDC_Transmit_FS()` 改为双缓冲发送，并在 USB 发送完成回调中继续发送积压数据。该改动解决了 shell 输出丢字、乱码的问题。

## FOC/QD4310 相关差异

相对原始 C 版，FOC 主控制环、电流环、速度环、角度环的核心控制流程没有作为 USB 修复目标被改动。存在的有效逻辑差异主要集中在抗齿槽补偿表存储：

- `UserLib/FOC/FOC.c`：抗齿槽补偿表由结构体内固定数组改为 `calloc()` 动态分配。
- `UserLib/FOC/FOC.h`：删除 `anticogging_map_storage[FOC_MAP_LEN]`，保留 `float *anticogging_map`。
- `UserLib/QD4310/QD4310.c`：抗齿槽表读写长度从错误的指针大小修正为 `FOC_MAP_LEN * sizeof(float)`，并增加空指针检查。

这些差异影响抗齿槽表的内存和存储读写，不是 USB 连接问题的直接原因，也不是电机闭环算法主体的改动。
