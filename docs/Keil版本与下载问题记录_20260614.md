# Keil 版本与下载问题记录

日期：2026-06-14

## 背景

当前 `main` 分支为已迁移并验证可用的 Keil 工程版本，工程路径为：

```text
D:\Desktop\FOC_QD4310\QDrive_FOC_Rebuild_Keil
```

本次排查目标是解决两个问题：

- Keil Rebuild 时出现大量警告，而普通 Build 不报警告。
- Keil 烧录后 USB 串口可枚举，但上位机无法正常打开设备或发送命令。

## 现象

### ARM Compiler V6.9 不可用

工程最初指定 ARM Compiler `V6.9`，但 `D:\Keil_5.40` 只注册了：

- `V6.22`
- `V5.06 update 5`

因此 Keil GUI 会提示：

```text
Target uses ARM-Compiler 'V6.9' which is not available.
Please review the installed ARM Compiler Versions.
```

### V6.22 Rebuild 警告

切到 `D:\Keil_5.40` 自带的 ARM Compiler `V6.22` 后，Rebuild 会出现大量：

```text
-Wnan-infinity-disabled
```

普通 Build 没有明显报警，主要是因为已有对象文件未全部重新编译；Rebuild 会全量编译，所以警告集中暴露。

### D 盘 Keil 下载后 USB 无法打开

即使固件可以编译并下载，使用 `D:\Keil_5.40` 原始 ST-Link 下载组件烧录后，设备会枚举成 COM 口，但打开串口时失败。表现类似：

```text
连到系统上的设备没有发挥作用
```

同一份固件如果用 `C:\Keil_v5` 的 ST-Link 下载组件烧录，USB 串口可以正常打开并执行 shell 命令。

## 处理过程

### 注册 ARM Compiler V6.9

将 `C:\Keil_v5\ARM\ARMCLANG` 注册到 `D:\Keil_5.40\TOOLS.INI`：

```text
ARMCCPATH2="C:\Keil_v5\ARM\ARMCLANG"  ("V6.9")
```

备份文件：

```text
D:\Keil_5.40\TOOLS.INI.codex-backup-20260614
```

### 工程保持使用 V6.9

最终工程继续使用已验证的 ARM Compiler `V6.9`，避免 V6.22 对 `NaN/Inf` 优化语义产生额外警告。

Keil 工程关键配置：

```xml
<pArmCC>6090000::V6.9::ARMCLANG</pArmCC>
<pCCUsed>6090000::V6.9::ARMCLANG</pCCUsed>
```

### 关闭 ClangAsOpt

`D:\Keil_5.40` 调用老版本 `V6.9` 时，如果使用 clang 集成汇编选项，会出现不兼容的汇编参数问题。工程中将：

```xml
<ClangAsOpt>0</ClangAsOpt>
```

这样启动文件 `startup_stm32g431xx_keil.s` 使用兼容路径汇编。

### 替换 D 盘 Keil 的 ST-Link 下载 DLL

确认二进制固件本身没有问题后，将 `D:\Keil_5.40` 的 ST-Link 下载 DLL 替换为 `C:\Keil_v5` 中已验证稳定的版本。

原文件备份：

```text
D:\Keil_5.40\ARM\STLink\ST-LINKIII-KEIL_SWO.dll.codex-backup-20260614
```

当前使用的稳定 DLL：

```text
C:\Keil_v5\ARM\STLink\ST-LINKIII-KEIL_SWO.dll
```

替换后，使用 `D:\Keil_5.40` 下载固件，USB 串口可正常打开。

## 最终验证

### Keil Rebuild

使用命令行调用：

```text
D:\Keil_5.40\UV4\UV4.exe -j0 -r Projects\MDK-ARM\FOC_QD4310_Keil.uvprojx
```

最终结果：

```text
Using Compiler 'V6.9', folder: 'C:\Keil_v5\ARM\ARMCLANG\Bin'
Program Size: Code=79716 RO-data=2572 RW-data=480 ZI-data=21536
0 Error(s), 0 Warning(s)
```

### Keil 下载

使用 `D:\Keil_5.40` 下载后日志显示：

```text
Erase Done.Programming Done.Verify OK.Application running ...
```

### USB 命令验证

设备枚举为 COM19 后，可以打开串口并执行命令：

- `version`
- `help`
- `info`
- `status`
- `disable`
- `status`

验证到的信息：

- Hardware version：`4310_6.1.0`
- Software version：`6.2.0`
- 电压约：`12.53V`
- 命令收发正常

## 结论

本次问题不是 BOOT0 Option Bytes，也不是 FOC 控制逻辑问题。

关键原因是：

1. `D:\Keil_5.40` 未注册工程需要的 ARM Compiler `V6.9`。
2. `V6.22` Rebuild 会暴露 `NaN/Inf` 相关警告，不适合作为当前已验证固件的基准编译器。
3. `D:\Keil_5.40` 原始 ST-Link 下载 DLL 烧录后会导致 USB 串口打开异常，替换为 `C:\Keil_v5` 的稳定 DLL 后恢复正常。

当前 `main` 分支已经记录并保留最终可用的 Keil 工程配置。
